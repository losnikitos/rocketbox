# Prompts

Content prompts are `Recipe` rows ([recipe.rb](/app/models/recipe.rb)), edited at `/app/recipes` with a tab per input folder. Each has a `body`, one example image, a type (`kind`: `generate_image` or `generate_video`, one AI call; or `stitch`, no AI and no prompt, joining the inputs, photos or videos, into a 9:16 video with ffmpeg, cut by its `effect`: `default` plays each input for 1 second in order, `doppler` lays the Doppler track from [lib/stitch](/lib/stitch) and cuts on its beat, each cut a random input other than the one before), an ordered list of inputs, and an output folder. Each input is a library folder (`inputs`, e.g. `[{ "folder_id" => 3 }]` for `inbox/interior`) and may repeat (two staff photos); a `generate_video` recipe takes exactly one. Results land in `output_folder_id`, a folder in the Photobank tree (default `photobank/ready`). The pipeline uses recipes twice: Inbox recipes polish one owner photo into the Photobank, Photobank recipes compose several photos into a Ready image.

A recipe's page, `/app/recipes/:id`, edits it inline and runs it: each input shows its folder (a dropdown) and the library media picked from it (`media_ids[i]` preselects input `i`; a media page's "Apply recipe" links there). Save and Run saves the form, then runs; Run runs the form as it is without saving it (a one-off prompt or options; changing the type needs a save); Save only saves. A run creates a `RecipeRun` ([recipe_run.rb](/app/models/recipe_run.rb)) with the picked media as ordered `RecipeRunInput` rows and an empty result media, and keeps the prompt (body, then shot and style bodies) as sent; `RecipeRun#run!` sends the media with it to a single AI call and attaches the result to that media. The run also keeps the cost and any error; the result media's page shows them. A run without a recipe records a version the owner dropped onto a media themselves; its input is the version's source.

Recipes carry default AI options — model, aspect ratio, size, quality (duration for video) — in an `options` column ([generation_options.rb](/app/models/concerns/generation_options.rb)). A run takes the options from the form; options the picked model doesn't offer fall back to the defaults.

Styles are `Style` rows ([style.rb](/app/models/style.rb)), edited at `/app/styles`: a name, a `body` with visual cues (lighting, camera, colour, mood) and example images. A style is a recipe input: a recipe takes one fixed style (`style_id`, the Style section on the recipe form), and every run keeps it as `style_id`. Its body is appended after the shot body. The initial set was imported from tadaaa's shooting styles: `db/styles.yml` holds names, bodies and public photo URLs, and `bin/rails styles:import` ([styles.rake](/lib/tasks/styles.rake)) upserts them by name.

Shots are `Shot` rows ([shot.rb](/app/models/shot.rb)), edited at `/app/shots` with a tab per `group`. Each one is a scene to shoot (e.g. "Empty Chair"), made of a name, a `body` and example images. A recipe can take a shot by naming a group in `shot_group` (the Shot input on the recipe form). Running that recipe means picking one shot from the group (a random one is preselected); the run keeps it as `shot_id`, and its body goes between the recipe body and the style body. Examples are for browsing only. The initial "Daily" set of barbershop scenes lives in `db/shots.yml`, and `bin/rails shots:import` ([shots.rake](/lib/tasks/shots.rake)) upserts it by name.

Service prompts are constants in the code that uses them:

| Constant | Used for |
|----------|----------|
| `Crawl::DEFAULT_DATA_INSTRUCTION` | Default data instruction for a crawl |
| `ExtractBusinessCard::INFO_PROMPT` / `LOGO_PROMPT` | Reading a business card |
| `ImproveLibraryMedia::PROMPT` | Improving a library image with AI |
