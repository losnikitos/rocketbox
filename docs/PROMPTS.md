# Prompts

Content prompts live in transformations ([transformation.rb](/app/models/transformation.rb)), each owned by one workflow step ([WORKFLOWS.md](/docs/WORKFLOWS.md)) and edited in the workflow's inspector ([controller](/app/controllers/accounts/transformations_controller.rb)). A transformation is the processing step: the type, the prompt (`body`), AI options and layer steps. `Transformation#run!(items:, folder:)` runs it on given items: media, prompts or reviews, as its type takes.

The type is the transformation's `kind`, the slug of a `Transformation::Type` class ([type.rb](/app/models/transformation/type.rb), registered in `Transformation::Type.all`). Its metadata (label, description, layer, …) are class methods and it makes a run's file in `#file`. Each type subclasses one of three groups, shown as tabs in the workflow's + Add popover:
- **Generation** ([generation.rb](/app/models/transformation/generation.rb)): one AI call with the prompt; `generate_image` or `generate_video` (images plus an optional prompt), or `llm` ([llm.rb](/app/models/transformation/llm.rb)): takes any prompts and images, or none, and writes one prompt, its body the instruction and the prompts and images fed to it the message, on the chat model picked in its settings, from those enabled in Active Admin (else RubyLLM's default).
- **Overlay** ([overlay.rb](/app/models/transformation/overlay.rb)): no AI and no prompt; lays the type's layer over one photo or video, as the same, filled from its one layer step (blank fields keep the layer's defaults): `fully_booked`, `daily` (its caption the prompt fed to it, if any, e.g. an LLM step's), `review` (filled from the 5-star review fed to it instead), `calendar`, `caption`, `text`.
- **Scripted** ([scripted.rb](/app/models/transformation/scripted.rb)): no AI; joins the inputs, photos or videos, into a 9:16 video with ffmpeg, the type deciding the cuts (`cuts`) and the layer values over each (`layer_values`, from `layer_steps[i]` by default): `steps` plays each input for 1 second in order; `doppler`, `welcome`, `black_eyed_peas`, `azzurro` and `gm_visuals` lay their track and cut at its cut ends, each cut a random input other than the one before (`gm_visuals` the inputs in the order they're connected); `welcome` takes one step and reveals its four lines one per cut over the first four cuts; `gm_visuals` speed-ramps each video (`retime`): fast at the cut's ends, slow through its middle.

Each scripted type is one folder, `reels/<slug>/`, autoloaded as `Reels::<Name>` ([reels.rb](/config/initializers/reels.rb)): `<slug>.rb` (the class), `<slug>.mp4` (the original reel, previewed on the form), `<slug>.wav` (its track) and `beats.csv` (cut ends in seconds), the last two made from the original by `beats.ipynb`. To add one from an Instagram reel, follow the [reel skill](/.cursor/skills/reel/SKILL.md): download it into a new folder, run the notebook, save its first frame as the type's cover (`app/assets/images/transformations/<slug>.jpg`), write the class (label, description, optional `layer`, `source_url`, `cuts` or `layer_values` overrides), and add it to `Transformation::Type.all`. What a step takes and where its results land are the workflow's folders and edges (see [WORKFLOWS.md](/docs/WORKFLOWS.md)).

A run creates a `TransformationRun` ([transformation_run.rb](/app/models/transformation_run.rb)) with its items as ordered `TransformationRunInput` rows and an empty result (a media, or a prompt for an LLM), and keeps the prompt (body, then the picked prompts' bodies) as sent in `prompt_text`; `TransformationRun#run!` makes the result's file or text. The run also keeps the cost and any error; the result media's page shows them and links to the workflow step that made it. A run without a transformation records a version the owner dropped onto a media themselves; its input is the version's source.

Transformations carry default AI options — model, aspect ratio, size, quality (duration for video) — in an `options` column ([generation_options.rb](/app/models/concerns/generation_options.rb)); options the picked model doesn't offer fall back to the defaults.

Prompts are `Prompt` rows ([prompt.rb](/app/models/prompt.rb)) in prompt folders under the Prompts root, browsed in the library like media folders (`/app/library/prompts/shots`) and edited by admins ([controller](/app/controllers/accounts/prompts_controller.rb)). Each one is a reusable piece of prompt text (e.g. the "Empty Chair" scene), made of a name, a `body` and example images; hand-written ones are shared (no `user`), ones an LLM step writes are its run's owner's. Photographic styles (lighting, camera, colour, mood; first imported from tadaaa's shooting styles) are prompts in `prompts/styles`. A prompt folder feeds a workflow step like a media folder ([WORKFLOWS.md](/docs/WORKFLOWS.md)): an Image or Video step run picks one prompt at random from each prompt folder feeding it (e.g. a shot and a style), kept as the run's inputs, their bodies appended after the transformation's body in arrow order, each under a `# <folder name>` header (slots to place them in the body are to come). Examples are for browsing only. The initial barbershop scenes live in `db/prompts.yml`, and `bin/rails prompts:import` ([prompts.rake](/lib/tasks/prompts.rake)) upserts them by name into `prompts/shots`.

Service prompts are constants in the code that uses them:

| Constant | Used for |
|----------|----------|
| `Crawl::DEFAULT_DATA_INSTRUCTION` | Default data instruction for a crawl |
| `Transformation::UpdateBusiness::DEFAULT_BODY` / `Transformation::ExtractLogo::DEFAULT_BODY` | Defaults for the Business card workflow steps (editable on the canvas) |
| `ImproveLibraryMedia::PROMPT` | Improving a library image with AI |
| `Transformation::Sort::DEFAULT_BODY` (`SortInboxMedia::PROMPT`) | Sort step default prompt (editable on the canvas); pick an Inbox subfolder for a photo or video |
