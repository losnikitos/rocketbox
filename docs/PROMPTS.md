# Prompts

Content prompts live in `Recipe` rows ([recipe.rb](/app/models/recipe.rb)), edited at `/app/recipes` with a tab per input folder. Each has one example image, an ordered list of inputs, a transformation and an output folder. The transformation ([transformation.rb](/app/models/transformation.rb)) is the processing step: the type, the prompt (`body`), AI options, a fixed style, a shot group and layer steps. It's a row of its own, so it can be shared and run without a recipe (`Transformation#run!(media:, folder:)`); the recipe form edits it through `transformation_attributes`.

The type is the transformation's `kind`, the slug of a `Transformation::Type` class ([type.rb](/app/models/transformation/type.rb), registered in `Transformation::Type.all`). Its metadata (label, description, layer, …) are class methods and it makes a run's file in `#file`. Each type subclasses one of three groups, shown as groups in the form's Type select:
- **Generation** ([generation.rb](/app/models/transformation/generation.rb)): one AI call with the prompt; `generate_image` or `generate_video`.
- **Overlay** ([overlay.rb](/app/models/transformation/overlay.rb)): no AI and no prompt; lays the type's layer over one photo or video, as the same: `fully_booked`, `daily`, `review` (filled from a 5-star review its runs pick), `calendar`.
- **Scripted** ([scripted.rb](/app/models/transformation/scripted.rb)): no AI; joins the inputs, photos or videos, into a 9:16 video with ffmpeg, the type deciding the cuts (`cuts`) and the layer values over each (`layer_values`, from `layer_steps[i]` by default): `steps` plays each input for 1 second in order; `doppler`, `welcome`, `black_eyed_peas`, `azzurro` and `gm_visuals` lay their track and cut at its cut ends, each cut a random input other than the one before; `welcome` takes one step and reveals its four lines one per cut over the first four cuts; `gm_visuals` speed-ramps each video (`retime`): fast at the cut's ends, slow through its middle.

Each scripted type is one folder, `reels/<slug>/`, autoloaded as `Reels::<Name>` ([reels.rb](/config/initializers/reels.rb)): `<slug>.rb` (the class), `<slug>.mp4` (the original reel, previewed on the form), `<slug>.wav` (its track) and `beats.csv` (cut ends in seconds), the last two made from the original by `beats.ipynb`. To add one from an Instagram reel, follow the [reel skill](/.cursor/skills/reel/SKILL.md): download it into a new folder, run the notebook, save its first frame as the type's cover (`app/assets/images/transformations/<slug>.jpg`), write the class (label, description, optional `layer`, `source_url`, `cuts` or `layer_values` overrides), and add it to `Transformation::Type.all`. Each input is a library folder and how many media a run takes from it (`inputs`, e.g. `[{ "folder_id" => 3, "count" => 2 }]` for two from `inbox/interior`), one input per folder; a run sees the picked media as one flat list. A `generate_video` recipe takes exactly one media. Results land in `output_folder_id`, a folder in the Photobank tree (default `photobank/ready`). The pipeline uses recipes twice: Inbox recipes polish one owner photo into the Photobank, Photobank recipes compose several photos into a Ready image.

A recipe's page, `/app/recipes/:id`, edits it inline and runs it: each input shows its folder (a dropdown), its count and the library media picked from it, a multi-select capped at the count (`media_ids[]` are the picks, kept on refresh and topped up at random; a media page's "Apply recipe" links there with that media). A run needs exactly each input's count from its folder. Save and Run saves the form, then runs; Run runs the form as it is without saving it (a one-off prompt or options; changing the type needs a save); Save only saves. A run creates a `TransformationRun` ([transformation_run.rb](/app/models/transformation_run.rb)) with the picked media as ordered `TransformationRunInput` rows and an empty result media, and keeps the prompt (body, then shot and style bodies) as sent; `TransformationRun#run!` sends the media with it to a single AI call and attaches the result to that media. The run also keeps the cost and any error; the result media's page shows them. A run without a recipe records a version the owner dropped onto a media themselves; its input is the version's source.

Recipes carry default AI options — model, aspect ratio, size, quality (duration for video) — in an `options` column ([generation_options.rb](/app/models/concerns/generation_options.rb)). A run takes the options from the form; options the picked model doesn't offer fall back to the defaults.

Styles are `Style` rows ([style.rb](/app/models/style.rb)), edited at `/app/styles`: a name, a `body` with visual cues (lighting, camera, colour, mood) and example images. A style is a recipe input: a recipe takes one fixed style (`style_id`, the Style section on the recipe form), and every run keeps it as `style_id`. Its body is appended after the shot body. The initial set was imported from tadaaa's shooting styles: `db/styles.yml` holds names, bodies and public photo URLs, and `bin/rails styles:import` ([styles.rake](/lib/tasks/styles.rake)) upserts them by name.

Shots are `Shot` rows ([shot.rb](/app/models/shot.rb)), edited at `/app/shots` with a tab per `group`. Each one is a scene to shoot (e.g. "Empty Chair"), made of a name, a `body` and example images. A recipe can take a shot by naming a group in `shot_group` (the Shot input on the recipe form). Running that recipe means picking one shot from the group (a random one is preselected); the run keeps it as `shot_id`, and its body goes between the recipe body and the style body. Examples are for browsing only. The initial "Daily" set of barbershop scenes lives in `db/shots.yml`, and `bin/rails shots:import` ([shots.rake](/lib/tasks/shots.rake)) upserts it by name.

Service prompts are constants in the code that uses them:

| Constant | Used for |
|----------|----------|
| `Crawl::DEFAULT_DATA_INSTRUCTION` | Default data instruction for a crawl |
| `ExtractBusinessCard::INFO_PROMPT` / `LOGO_PROMPT` | Reading a business card |
| `ImproveLibraryMedia::PROMPT` | Improving a library image with AI |
