# Prompts

Content prompts live in transformations ([transformation.rb](/app/models/transformation.rb)), each owned by one workflow step ([WORKFLOWS.md](/docs/WORKFLOWS.md)) and edited in the workflow's inspector ([controller](/app/controllers/accounts/transformations_controller.rb)). A transformation is the processing step: the type, the prompt (`body`), AI options, a fixed style, a prompt folder and layer steps. `Transformation#run!(media:, folder:)` runs it on given media.

The type is the transformation's `kind`, the slug of a `Transformation::Type` class ([type.rb](/app/models/transformation/type.rb), registered in `Transformation::Type.all`). Its metadata (label, description, layer, …) are class methods and it makes a run's file in `#file`. Each type subclasses one of three groups, shown as tabs in the workflow's + Add popover:
- **Generation** ([generation.rb](/app/models/transformation/generation.rb)): one AI call with the prompt; `generate_image` or `generate_video`.
- **Overlay** ([overlay.rb](/app/models/transformation/overlay.rb)): no AI and no prompt; lays the type's layer over one photo or video, as the same, filled from its one layer step (blank fields keep the layer's defaults): `fully_booked`, `daily`, `review` (filled from a 5-star review its runs pick instead), `calendar`, `caption`, `text`.
- **Scripted** ([scripted.rb](/app/models/transformation/scripted.rb)): no AI; joins the inputs, photos or videos, into a 9:16 video with ffmpeg, the type deciding the cuts (`cuts`) and the layer values over each (`layer_values`, from `layer_steps[i]` by default): `steps` plays each input for 1 second in order; `doppler`, `welcome`, `black_eyed_peas`, `azzurro` and `gm_visuals` lay their track and cut at its cut ends, each cut a random input other than the one before; `welcome` takes one step and reveals its four lines one per cut over the first four cuts; `gm_visuals` speed-ramps each video (`retime`): fast at the cut's ends, slow through its middle.

Each scripted type is one folder, `reels/<slug>/`, autoloaded as `Reels::<Name>` ([reels.rb](/config/initializers/reels.rb)): `<slug>.rb` (the class), `<slug>.mp4` (the original reel, previewed on the form), `<slug>.wav` (its track) and `beats.csv` (cut ends in seconds), the last two made from the original by `beats.ipynb`. To add one from an Instagram reel, follow the [reel skill](/.cursor/skills/reel/SKILL.md): download it into a new folder, run the notebook, save its first frame as the type's cover (`app/assets/images/transformations/<slug>.jpg`), write the class (label, description, optional `layer`, `source_url`, `cuts` or `layer_values` overrides), and add it to `Transformation::Type.all`. What a step takes and where its results land are the workflow's folders and edges (see [WORKFLOWS.md](/docs/WORKFLOWS.md)).

A run creates a `TransformationRun` ([transformation_run.rb](/app/models/transformation_run.rb)) with its media as ordered `TransformationRunInput` rows and an empty result media, and keeps the prompt (body, then picked prompt and style bodies) as sent in `prompt_text`; `TransformationRun#run!` sends the media with it to a single AI call and attaches the result to that media. The run also keeps the cost and any error; the result media's page shows them and links to the workflow step that made it. A run without a transformation records a version the owner dropped onto a media themselves; its input is the version's source.

Transformations carry default AI options — model, aspect ratio, size, quality (duration for video) — in an `options` column ([generation_options.rb](/app/models/concerns/generation_options.rb)); options the picked model doesn't offer fall back to the defaults.

Styles are `Style` rows ([style.rb](/app/models/style.rb)), edited at `/app/styles`: a name, a `body` with visual cues (lighting, camera, colour, mood) and example images. A transformation takes one fixed style (`style_id`), and every run keeps it as `style_id`. Its body is appended after the picked prompt's body. The initial set was imported from tadaaa's shooting styles: `db/styles.yml` holds names, bodies and public photo URLs, and `bin/rails styles:import` ([styles.rake](/lib/tasks/styles.rake)) upserts them by name.

Prompts are `Prompt` rows ([prompt.rb](/app/models/prompt.rb)), edited at `/app/prompts` with a tab per `folder`. Each one is a reusable piece of prompt text (e.g. the "Empty Chair" scene), made of a name, a `body` and example images. A transformation can take a prompt by naming a folder in `prompt_folder`. A step run picks one prompt from the folder at random; the run keeps it as `prompt_id`, and its body goes between the transformation's body and the style body. Examples are for browsing only. For now a folder is just a name (`folder` string). Proper prompt folders and tags, like media folders, are planned. The initial "Shots" folder of barbershop scenes lives in `db/prompts.yml`, and `bin/rails prompts:import` ([prompts.rake](/lib/tasks/prompts.rake)) upserts it by name.

Service prompts are constants in the code that uses them:

| Constant | Used for |
|----------|----------|
| `Crawl::DEFAULT_DATA_INSTRUCTION` | Default data instruction for a crawl |
| `ExtractBusinessCard::INFO_PROMPT` / `LOGO_PROMPT` | Reading a business card |
| `ImproveLibraryMedia::PROMPT` | Improving a library image with AI |
